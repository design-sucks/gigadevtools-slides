# Project data

deck.json has schema:1, title, version (default 1), slides and optional order/motion. Each slide has a unique safe id, label, section, topic, sourceNumber, header (full/number/none), blocks and optionally html. Optional `navigationLabel` and `navigationTopic` override navigation strings; raw labels/topics remain in source metadata. Default navigation removes only a one or two digit slash prefix, or a punctuation prefix matching sourceNumber; explicit navigation strings preserve intentional numbered sections. Optional `background` is `{type:"color",value:"#RRGGBB"}`, `{type:"gradient",value:"linear-gradient(...)"}`, or `{type:"image",asset:"assets/file.png",focal:"50% 50%",size:"cover"}` (`position` aliases `focal`). For a full-viewport decoration image background, optional `wash:"radial-gradient(...)"` or `wash:"linear-gradient(...)"` paints on the full `.gd-slide-background::before` layer, including reading gutters; it moves with the background and resets to 1920×1080 for export. Keep the source image as `asset` and do not duplicate the wash in `slide.html`. Run `node scripts/test_image_background_wash.mjs /absolute/qa-directory` to check reading, narrow, export, save/reopen and malformed values. Unsupported CSS and washes on non-image backgrounds are rejected. Backgrounds fill the 1920×1080 slide independently of the 1696×874 safe content area; local images are embedded for offline use. IDs start with a letter and contain letters/digits/underscore/hyphen. Order contains included slide IDs only; slides can retain excluded records. Section/topic stay with the ID, never with its current array index.

extract_pptx.py produces blocks: text (paragraphs and inline runs), table (rows/cells/paragraphs), chart (series/categories/values), image (asset), media (file and poster), group (ancestry), geometry and unsupported. Source part/object ID and transforms retain traceability. Direct `p:bg` XML is retained as `sourceBackground` evidence; picture objects exactly matching the slide canvas are flagged `backgroundCandidate` and keep raw EMU geometry. These are review evidence, not automatic rendering decisions: map a confirmed local asset to the slide `background` field or declare a rendered fallback. It extracts content rather than implementing PowerPoint inheritance/layout/rendering. Shape geometry and SmartArt need visual reconstruction or a declared rendered fallback. Do not claim arbitrary PPTX 1:1 import. Current extraction audit covers visible slide XML text; compare chart values separately and inspect master/layout material in the source proof.

Embedded SVG takes priority even when PowerPoint supplies no PNG fallback. Retain the original vector bytes. PPTX runs retain explicit `trackingPt` and paragraphs retain direct `paragraphPropertiesXml` when present. Use tracking as inline styling inside the editable paragraph. Table `rows` remain the text/data source. `tableLayout` adds column widths, row heights, merge attributes and the original cell/table properties. Groups and shapes preserve local DrawingML properties, `paintOrder` within their parent, and connector endpoint IDs when available. Reconstruct meaningful connections against the source render. Group coordinates, inherited styles and complex masks need visual review.

A video or audio picture with an available internal relationship becomes one `media` block at the original picture ID, with its source geometry, poster if present, relationship and `mediaTiming` evidence keyed by the source object. Commands, conditions and settings help review triggers. They do not implement automatic playback. An unavailable media file is flagged for review. The assembly draft embeds available posters and media with native controls.

For reviewed output, slide.html replaces the assembly draft for that slide. Use semantic h1/h2/p/lists/tables and SVG where appropriate. It is inserted inside .gd-content, within the independent .slide-inner motion layer; keep UI outside it. Refer to local assets as src="assets/name.png"; the builder embeds them. The builder rejects scripts, event handlers and javascript URLs in body markup. It is not an arbitrary HTML application importer. Local assets/fonts must reside inside the project directory. Remote resources are not an offline asset solution.

Source notes are stored in the project and deliberately omitted from public HTML. Only include notes in a public/presenter feature when requested. PPTX footer/date/page placeholders are separated from body. Automatic fields and ambiguous geometric footers require review; do not delete meaningful source content by position alone.

The shell's SalesKitUI.setOrder([...]) validates IDs and prevents empty/duplicate orders. SalesKitUI.exportDocument('work') returns a next-version standalone HTML with all slides and the selected order; 'bundle' retains only selected slides. GigaDevDeck.getState() exposes the active selection/settings. prepareExport() is a one-way preparation for an isolated export page, not a user editor toggle. It commits text, closes dialogs, finishes motion and reveals per-slide metadata. Excluded slides stay excluded; numbers reflect current order.

The runtime text editor supports ordinary HTML content. Authored journal targets use a unique `data-source-id` on one text element per slide; the editor assigns its own stable `data-eid`. Preparation `sourceId` must resolve once, and its before/after value must agree with the target and applied state. Text inside SVG, raster artwork, media, canvas or external iframes is not promised editable. For meaningful labels, prefer HTML text or explicitly declare a graphical fallback.

Wheel/touch navigation in the accepted shell v06 matches SalesKit v25: native continuous scrolling, no wheel interception, no mandatory snapping. The paused WAAPI opacity/blur follows scroll position and immediately follows reversal. A stopped wheel may leave the deck between slides; metadata identifies the nearest slide. Keyboard/clicker navigation retains its separate timed exit/entry. Do not equate these two input paths or add a per-gesture lock. The checker exercises small wheel deltas, reversal and multi-slide scrolling, not just completed slide changes. Header counter alignment remains independent of breadcrumb visibility.

The browser uses `--gd-scroll-height` for a full-window scroll page, and places the fixed 1920×1080 composition inside it with the same fit/safe-area margins. The scrollport must reach the top and bottom of the window, including in tall windows and presentation mode. A scaled 1080px scroll viewport would introduce letterbox clipping through text during scroll. Export/print reset scroll height to 1080 and composition offset to 0. Check the actual ancestor clip rectangles and partial-scroll screenshots; animation curve parity is insufficient.

The scrollport and page heights are unscaled viewport pixels. `--gd-view-scale` affects only the intrinsic content. The shared v25 easing/timing is retained; scroll uses an independent motion layer at the v25 responsive zoom, and `--gd-motion-gain` converts keyboard-group blur/translate units using that zoom divided by content fit scale. This prevents double-scaling: same wheel deltas give the same screen displacement, fade progress and effective blur as v25. Test repeated wheel input and reversal at the same viewport; comparing curves at normalized percentages can hide wrong speed.

When a source HTML is available for motion parity, run `node scripts/check_motion_reference.mjs /absolute/reference.html /absolute/candidate.html /absolute/NEW_QA_DIRECTORY`. It replays the same wheel sequence at four viewports and compares actual screen displacement, opacity, blur and clipping. It needs two slides and the SalesKitMotion bridge; it is optional for unrelated source runtimes.

The .slide-inner motion layer fills the 1920×1080 slide and remains separate from fitted .gd-content. Scroll filtering uses the same responsive CSS zoom as v25, so the browser paints blur at the reference resolution; intrinsic 1920×1080 content fits inside it. Keyboard groups still come from the content children, with compensated units for their separate scale. Show and export headers use the same 48px left/right, 30px top, SB Sans Display Regular 20px coordinates at canonical size. Export keeps the moving frame full-size and positions the untransformed 1696×874 safe content at 112,120.

The show header uses the supplied AI_PDLC_Status_v05 reference: SB Sans Display Regular (400), 20px font / 24px line height in intrinsic 1920×1080 units, scaled with `--gd-view-scale`. The show footer counter uses Display Regular 13px/1.2 in screen units. Keep the existing narrow-screen 10px top-navigation floor, other UI/body typography, header positions, palette, metadata logic and export styles. The included Display Regular OTF matches the reference font bytes; avoid synthetic bold or a substituted Text face.

Reading backgrounds fill the entire viewport behind the transparent navigation; the 16:9 composition keeps logical UI gutters. Background paint is a direct child of `.slide-inner`, before `.gd-content`; attach washes to `.gd-slide-background::before` rather than static `.slide::before`. Export/print explicitly reset the paint to 1920×1080. Test both image and gradient backgrounds at partial scroll positions.

Native graphic frames (tables/charts) carry their own `p:xfrm`; shapes/pictures use `p:spPr/a:xfrm`, groups use `p:grpSpPr/a:xfrm`. Consume the recorded own-object transform, not the first descendant transform. Group coordinate transforms and unsupported effects still need review. A missing table transform is a blocker for geometry preservation, not permission to place every cell at zero.

## Legacy structured compositions (Maker 0.20.0+)

For new design work select the [accepted reference pack](reference-pack.md) and author adaptive slide HTML. The schema below remains compatible with existing pinned renderer projects.

A reviewed slide may use `composition` instead of `html`:

```json
{"id":"decision","label":"Comparison","blocks":[],"composition":{"id":"comparison","version":"1.0.0","data":{"title":"Which option fits?","columns":["Criterion","A","B"],"rows":[["Setup","Fast","Custom"],["Support","Standard","Specialist"],["Scale","Small","Large"]],"highlightColumn":2}}}
```

The builder rejects simultaneous html/composition and mismatched pattern versions. It includes scoped composition CSS only when used. Read the selected catalog record/example for fields and capacity. Optional `highlightColumn` is zero-based; omit it for an unbiased factual matrix. Text values accept `{text,sourceId,runs,href}` and card icons accept `{icon,iconAlt,iconSourceId,accent}` on their item. Body paragraph arrays and footer arrays preserve separate source targets. Table sourceId uses `tableSourceId`. Keep source blocks for audit; only composition is rendered. `sampleOnly:true` is reserved for the library-demo deck purpose and cannot appear in an ordinary delivery. See [compositions](compositions.md).

## Composition planning and explicit final build

Record one reviewed decision per ordered slide as described in [composition decisions](composition-decisions.md). `--final --composition-plan plan.json` rejects ordinary block assembly and incomplete plans, while the existing default build remains a draft-compatible path. This gate checks structure, not the truth of recorded visual or capacity review.

## Scoped slide styles

New themes can supply `slideCss` as a CSS string. The builder wraps it in native `@scope (.gd-content)`, limiting its selectors to slide content in supporting browsers. Supply fonts via the theme's existing font mechanism; `@font-face` and `@import` are rejected inside `slideCss`. Existing `css` and `cssFile` remain legacy global styles: diagnose them with `node scripts/check_css_scope.mjs deck.html theme.json`, which checks `css` and `cssFile` against the current shell DOM and emits review items for unproven scopes. Its scope check is not proof for inactive UI. Migrate legacy styles only after visual and runtime tests, including actual fonts, nested rules and browser support.

An optional per-slide `shellInk` is `light`, `dark`, or `auto` (default). It chooses light or dark interface text for that slide's background and follows the stable slide ID through reorder and save/reopen; it does not recolor the slide content. Check actual contrast on the selected background, in reading, presentation and export; mixed backgrounds can require a backing surface rather than a single ink color.

Imported draft media uses unambiguous PPTX `cMediaNode` evidence for mute, indefinite loop and volume (0–100000 maps to 0–1); ambiguous or missing settings remain review items. Authored HTML can supply `muted`, `loop` and `data-gd-volume="0.8"`. The runtime retains volume and mute changes when saving. Playback requires browser permission and user gesture; inspect any `gd-media-error`. Space controls the active media except in editing/form controls and dialogs. Other triggers and unsupported timing require explicit review.

For an explicitly accepted 16:9 whole-slide image used as a viewing fallback, set image background `role: "content-frame"`. The builder fits that frame to the presentation canvas in reading, presentation and export instead of cropping it as decorative cover. Check source aspect ratio and actual corner visibility; other aspect ratios are not automatically preserved by this mode. A full-slide image is not editable content and does not satisfy an editable delivery without explicit agreement.

Use `build.py ... --external-media` only for an explicitly identified offline package: video/audio are stored in `<HTML-stem>_media/` with a SHA-256 manifest; other embedded assets remain in the HTML. Deliver the HTML and that folder together. Work/bundle saves still reference that folder and must be moved together with it; a saved HTML alone is not standalone. Run `python3 scripts/check_portability.py presentation.html`, move a copy of the complete package to a new directory, block network access, and verify media decoding, playback and work/bundle reopening. Static checks do not verify audio, dynamic URLs or nested SVG dependencies. Without `--external-media`, the builder embeds project media in the standalone HTML.

For new projects set `cssIsolation: "strict"` in `deck.json`. The builder scopes theme `css`, `cssFile` and `slideCss` to `.gd-content`; inline slide `<style>` and `<link>` elements are rejected. Declare font files via theme `fonts`/`builtinFonts`; `@font-face` and `@import` in scoped CSS are rejected, and animation names must start `gdslide-`. Existing projects default to `legacy` to avoid unreviewed migration. Strict mode permits only @media, @supports, @container and namespaced @keyframes at-rules; it rejects global registrations such as @property and @layer and CSS escapes outside strings. It checks balanced CSS before wrapping, but does not replace browser tests or automatically validate all CSS syntax. Test source fonts, nested rules and animations in each supported browser.

Set `mediaFrame: "full"` only for a slide deliberately authored around one video. This uses the full 1920×1080 canvas instead of the text-safe frame; overlays in that slide must be authored in full-canvas coordinates. The builder requires exactly one video with a poster. Video uses `object-fit: contain` on black, preserving its aspect ratio. In static export it is stopped and reset to its poster, with controls removed. Verify placement, poster and interaction in reading, presentation and export. Default `mediaFrame: "content"` retains the normal content frame.

When preparing a project from an extracted PPTX, inspect each video slide's source render and the media block's original geometry and poster. If the source makes one video the intended full-canvas content, with no other meaningful slide content, set that slide's `mediaFrame` to `"full"` in the derived project as part of assembly; do not alter the PPTX or rely on the user to supply a shell attribute. In authored `html`, preserve the extracted source ID, poster, video settings and every source overlay. The builder writes `data-gd-media-frame="full"` on the slide. A sole direct video selects viewport-pixel sizing; a single direct `<video controls>` inside one full-frame `<div>` wrapper can also receive the scoped native-control hitbox adjustment when all overlay geometry is verifiably outside the reserved bottom control band. Verify source frame and video geometry independently, then check the actual aspect fit, controls, overlays, poster and saved/reopened result.

A geometry match alone does not establish intent. Keep the default `"content"` and request visual review if the source has an uncertain frame or missing poster. Full-frame overlays must remain intact; unsupported wrappers, extra media, transforms, effects, clipped/unknown geometry, animated overlays or any overlay intersecting the conservative control band are rejected for the hitbox adjustment. Inspect `GigaDevMedia.getHitAreaStatus()` for the current reason; the browser-only check does not authenticate PPTX geometry. Video fullscreen and operating-system controls remain browser-dependent.

For a verified active full-frame video, the runtime can use viewport-pixel layout in reading and presentation: it removes nested frame scaling and applies the same uniform scale to each validated, absolutely positioned overlay. A sole direct video with exact authored 1920×1080 inline dimensions is also handled when the existing portrait rule has unscaled its frame. Other custom geometry and overlays whose coordinates cannot be verified retain the normal layout. `GigaDevMedia.getPanelLayoutStatus()` reports whether this runtime-only adaptation is active; it is disabled during edit/export and never stored in saved HTML. Recheck after source CSS or script changes: arbitrary CSSOM edits and programmatic listeners are not fully enumerable. For an eligible full-frame video intersecting shell hit areas, the runtime narrows the invisible footer trigger to the rightmost 12 CSS pixels, bridges hover to the unchanged footer and limits the slide progress input to its visible 5-pixel track. Verify actual panel width, video/overlay positions, native controls, Space, navigation, edit and save/reopen on the target browser. Playback, fullscreen, native overflow and audible output remain browser-dependent.


A static, noninteractive source overlay may explicitly opt in to letting pointer events reach the video beneath it, for example `<div data-source-id="s1-o2" data-gd-video-pass-through="true">…</div>`. The attribute is an **author assertion** that neither the element nor its descendants has JavaScript listeners or delegated application handlers, and that the element is intended to be passive. Do not add it to overlays with links, inputs, roles, tabindex, inline handlers, custom event behavior or uncertain interaction. The runtime rejects detectable interactive attributes/elements and unsafe geometry and reports `GigaDevMedia.getPassThroughStatus()`; it cannot enumerate arbitrary programmatic or delegated listeners. An inventory such as Chrome CDP is only a point-in-time aid, not proof of future or delegated behavior. Pass-through applies in reading and presentation only, is disabled in edit/export, and never removes the source text or shape. Without the explicit attribute, existing overlay hit-testing is unchanged.

## RC14 shell ink and transparent surfaces

The title and navigation bubbles pair their text and icon ink with a translucent light or dark fill. `shellInk="auto"` follows the theme; explicit `light` uses a dark surface and `dark` uses a light surface, including the title pill. Active navigation uses a contrasting surface/ink pair. Surface opacity remains high enough to keep text contrast above 4.5:1 and icons above 3:1 on black, white and sampled saturated colors. Color calculations bound alpha compositing; they do not sample every image pixel.

## Section-aware navigation (RC16)

Before authoring, inspect actual PPTX/outline dividers and mark reviewed section title slides with `navigationRole: "divider"` (a `composition.id: "divider"` also qualifies). Their visible heading sets the section for subsequent source-order slides until the next divider. Do not infer a divider merely from short text. Explicit `navigationSection` overrides a page (empty clears its header section); explicit `section` is respected. Metadata resolves in deck.slides order and stays attached to stable IDs during reorder/exclude/save; an excluded divider does not erase its members' context.

The top breadcrumb removes a topic equal to the actual first h1/h2 and removes repeated section/title/topic values, ignoring cosmetic punctuation/case/spacing. It preserves an explicit empty `navigationTopic`; the runtime must not refill it from the label. Empty breadcrumbs leave the page number in place. `navigationSection` in output metadata retains the full section even on a divider whose header is suppressed. Sidebar labels remain nonempty for finding pages; use `navigationLabel` for a reviewed concise label and `navigationTopic` only for useful distinct context. Only the authoring agent summarizes semantics; the builder performs no speculative summarization or title deletion in slide bodies. Raw source labels/topics/sections are retained separately.


## Source presentation roles (RC18)

Use [presentation roles](presentation-roles.md) for `background.sourceId`/layers and reviewed `sourceChrome`. Original source blocks stay intact. The builder routes paint to the full reading viewport and source chrome to canonical show/export metadata; it does not hide body titles or data.


## User navigation overrides (RC19)

The [navigation editor](navigation-editor.md) saves optional per-slide `navigationLabelOverride` and `showNavigationOverride: {section, topic}`. Generated defaults remain in the resolved `baseLabel`, `baseSection`, `baseTopic`; built metadata keeps those defaults plus overrides. DOM/show/export use effective values. Overrides apply after automatic duplicate suppression, are per stable slide ID, and never propagate to the rest of a section. Lists need a nonempty name (max120 UTF-16 units); both show fields may be empty (max160 each). Unknown keys/types/control characters fail the build. These fields change no body content, header mode or page counter. Reconcile saved **work** HTML before rebuilding from JSON.
