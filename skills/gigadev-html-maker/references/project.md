# Project data

deck.json has schema:1, title, version (default 1), slides and optional order/motion. Each slide has a unique safe id, label, section, topic, sourceNumber, header (full/number/none), blocks and optionally html. IDs start with a letter and contain letters/digits/underscore/hyphen. Order contains included slide IDs only; slides can retain excluded records. Section/topic stay with the ID, never with its current array index.

extract_pptx.py produces blocks: text (paragraphs and inline runs), table (rows/cells/paragraphs), chart (series/categories/values), image (asset), group (ancestry), geometry and unsupported. Source part/object ID and transforms retain traceability. It extracts content rather than implementing PowerPoint inheritance/layout/rendering. Shape geometry and SmartArt need visual reconstruction or a declared rendered fallback. Do not claim arbitrary PPTX 1:1 import. Current extraction audit covers visible slide XML text; compare chart values separately and inspect master/layout material in the source proof.

For reviewed output, slide.html replaces the assembly draft for that slide. Use semantic h1/h2/p/lists/tables and SVG where appropriate. It is inserted inside .gd-content, within the independent .slide-inner motion layer; keep UI outside it. Refer to local assets as src="assets/name.png"; the builder embeds them. The builder rejects scripts, event handlers and javascript URLs in body markup. It is not an arbitrary HTML application importer. Local assets/fonts must reside inside the project directory. Remote resources are not an offline asset solution.

Source notes are stored in the project and deliberately omitted from public HTML. Only include notes in a public/presenter feature when requested. PPTX footer/date/page placeholders are separated from body. Automatic fields and ambiguous geometric footers require review; do not delete meaningful source content by position alone.

The shell's SalesKitUI.setOrder([...]) validates IDs and prevents empty/duplicate orders. SalesKitUI.exportDocument('work') returns a next-version standalone HTML with all slides and the selected order; 'bundle' retains only selected slides. GigaDevDeck.getState() exposes the active selection/settings. prepareExport() is a one-way preparation for an isolated export page, not a user editor toggle. It commits text, closes dialogs, finishes motion and reveals per-slide metadata. Excluded slides stay excluded; numbers reflect current order.

The runtime text editor supports ordinary HTML content. Text inside SVG, raster artwork, media, canvas or external iframes is not promised editable. For meaningful labels, prefer HTML text or explicitly declare a graphical fallback.

Wheel/touch navigation in the accepted shell v06 matches SalesKit v25: native continuous scrolling, no wheel interception, no mandatory snapping. The paused WAAPI opacity/blur follows scroll position and immediately follows reversal. A stopped wheel may leave the deck between slides; metadata identifies the nearest slide. Keyboard/clicker navigation retains its separate timed exit/entry. Do not equate these two input paths or add a per-gesture lock. The checker exercises small wheel deltas, reversal and multi-slide scrolling, not just completed slide changes. Header counter alignment remains independent of breadcrumb visibility.

The browser uses `--gd-scroll-height` for a full-window scroll page, and places the fixed 1920×1080 composition inside it with the same fit/safe-area margins. The scrollport must reach the top and bottom of the window, including in tall windows and presentation mode. A scaled 1080px scroll viewport would introduce letterbox clipping through text during scroll. Export/print reset scroll height to 1080 and composition offset to 0. Check the actual ancestor clip rectangles and partial-scroll screenshots; animation curve parity is insufficient.

The scrollport and page heights are unscaled viewport pixels. `--gd-view-scale` affects only the intrinsic content. The shared v25 easing/timing is retained; scroll uses an independent motion layer at the v25 responsive zoom, and `--gd-motion-gain` converts keyboard-group blur/translate units using that zoom divided by content fit scale. This prevents double-scaling: same wheel deltas give the same screen displacement, fade progress and effective blur as v25. Test repeated wheel input and reversal at the same viewport; comparing curves at normalized percentages can hide wrong speed.

When a source HTML is available for motion parity, run `node scripts/check_motion_reference.mjs /absolute/reference.html /absolute/candidate.html /absolute/NEW_QA_DIRECTORY`. It replays the same wheel sequence at four viewports and compares actual screen displacement, opacity, blur and clipping. It needs two slides and the SalesKitMotion bridge; it is optional for unrelated source runtimes.

The .slide-inner motion layer is separate from fitted .gd-content. Scroll filtering uses the same responsive CSS zoom as v25, so the browser paints blur at the reference resolution; intrinsic 1920×1080 content fits inside it. Keyboard groups still come from the content children, with compensated units for their separate scale. Export restores the original inner box and an untransformed content wrapper.

Presentation-only navigation typography follows the supplied AI_PDLC_Status_v05 reference: SB Sans Display Regular (400), 20px font / 24px line height in intrinsic 1920×1080 units. Scale that text with --gd-view-scale instead of a viewport-width cap. The show footer counter uses Display Regular 13px/1.2 in screen units. Keep the existing narrow-screen 10px top-navigation floor, other UI/body typography, header positions, palette, metadata logic and export styles. The included Display Regular OTF matches the reference font bytes; avoid synthetic bold or a substituted Text face.
