# Compact reading and full-window motion

Reading has variable page pitch; showing/export/thumbnails keep the original 1920×1080 composition. Compact reading changes page pitch only; preserve the original body origin, minimum height and internal centering. The previous top-aligned natural-height variant shifted every slide and is a rejected regression. Keep a single shared runtime, not separate hand-patched HTML copies.

For suitable authored slides, use a direct `.gd-content > [data-gd-flow]` normal-flow root that retains its original minimum composition height. Put its main sections in direct children; mark a final short caption with `data-gd-tail`. Do not apply the marker to absolute/fixed geometry without first adapting and checking it. Unmarked slide bodies keep full-page fallback. Do not infer flow eligibility from text alone.

`flow.js` measures natural body and primary sections at fitted scale after fonts/layout. It keeps the same contentTop from the shared 16:9 fit, with the original 874px minimum body height and authored alignment. It adapts pitch, protects full footer bounds with a 40 screen-pixel gap, and adds tail space so the last slide can align. The reference-calibrated gap uses the SalesKit v26 ~742px body plus 18px incoming motion, with a 96px lower bound. The 55%-viewport pitch floor intentionally limits compression on narrow fixed-composition screens; it does not reproduce SalesKit's mobile text reflow. Inspect dense, sparse and mixed fixed/flow pages for the actual deck.

Keep `#slides` unscaled and its paint clip equal to the whole browser window. The per-page overflow must be visible, and the `.slide-inner` paint layer must retain the full viewport height even when page pitch is shorter. Transparent overlapping layers must not intercept editing/link clicks outside actual content. Never introduce a fixed 16:9 mask or per-page blur clipping in free reading.

Motion progress in compact reading uses adjacent anchor distances: incoming uses the preceding interval, outgoing uses its own interval to the next slide. Keep the source easing/keyframes and screen-space blur/translate magnitudes, but finish each fade at its neighboring anchor. Using the full viewport with a shorter page leaves a visible previous-slide footer; that v17.1 behavior is rejected. At rest show only the anchored slide. Between anchors show only their two slides. Whole-slide temporary visibility/opacity effects enforce this also with motion off/editing; they never crop content and are not serialized. Clear them for show/export/print and after order changes. Preserve them during keyboard exits. Native wheel/touch stay native, without snapping, cooldowns or gesture capture. Edits and undo must recalculate reading pitch.

On show/export/thumbnail entry, remove compact flags and restore the original 874px body within the 1920×1080 canvas. Saved HTML must strip transient page pitch, flow offsets and tail settings while preserving semantic markers and all current content, settings and order. Recalculate after reopen.

Only when this behavior changes, run `check_compact.mjs` on the bundled demo and compare curves with a supplied reference using `check_motion_reference.mjs REFERENCE CANDIDATE NEW_QA --anchor-progress`. Default mode compares raw wheel pixels and remains suitable for uncompressed geometry; it must not be presented as a compact-page equivalence test. Native wheel speed is tested separately by check.mjs. Review partial-scroll screenshots in both themes at wide/tall/narrow sizes. Layout metrics alone do not establish visible clipping quality. The bundled demo test compares 104 heading/body anchors with the measured pre-compact v02 fixture, including the cover and ending; bounds-only tests previously missed their vertical shift. It also checks 208 settled visibility states with motion on/off, all-slide show/export, thumbnail geometry, text editing/undo, last-page reachability and N/M. For new deck content, also inspect every actual slide; the fixture does not prove arbitrary slide geometry.
