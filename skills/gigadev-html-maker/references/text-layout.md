# Text preparation and rendered line review

For a concrete reading viewport run `node scripts/check_text_layout.mjs deck.html --viewport=1280x800 --actual-fonts`; inspect 1920x1080 and 390x844 where relevant. The report records the file hash, CSS font size, estimated screen size, content scale, requested font family and measured line widths. `--actual-fonts` asks Chromium for the fonts that rendered each target's glyphs; compare the result with the source requirements. The screen estimate uses the element’s rendered-to-layout width and reports content scale and the estimated additional nested scale separately. Rotations, nonuniform transforms and mixed inline sizes still need visual review. With `--inventory`, it reports nominal source points, normalized canvas pixels, source family and inherited size provenance; table cells map through their source table when there are no merges. `--actual-fonts` compares source families to rendered glyph families as a review signal. Font evidence is limited to the rendered browser and glyphs; family aliases may differ. Readability remains a visual judgment.

## Before layout

Before layout, read every authored text block in context. Preserve names, terminology, model versions, numbers, links and code. For ordinary requests, correct clear spelling, grammar and punctuation mistakes in the authored project before building; do not use a broad dictionary replacement list. For each meaning-level correction, write a reversible `preparationChanges` entry with the exact `sourceId`, `before`, `after`, `actor:"llm"`, and `kind:"text"`. Re-read the corrected sentence in its slide context. Put uncertain wording in pending proposals. For exact-copy requests, do not make meaning-level edits; use `--typography review` to show safe mechanical proposals or `--typography off` for no changes. Use one stable `data-source-id` on each authored logical paragraph and keep emphasis and links inline. Put source line wraps into the same paragraph; preserve intentional breaks.

```sh
python3 scripts/build.py /absolute/project/deck.json /absolute/new-deck.html --typography apply
```

Ordinary builds default to `--typography apply`. `apply` normalizes supported typography and creates reversible applied journal entries. `review` generates pending entries and leaves the HTML copy as authored. `off` disables automatic normalization. Safe rules cover paired straight quotes around simple Russian phrases, spaced dash before explanatory «это», «значит» or «вот», repeated spaces between Russian words, and spaces before punctuation. Apply them only to plain, single-line, source-bound headings, paragraphs, list items, captions and quotations in authored HTML. Blocks with inline markup, existing journal targets, technical strings, non-Russian language markup and blocks marked `data-gd-typography="off"` are excluded to preserve links and emphasis. Review these separately without rewriting markup or numbers. This pass does not determine spelling, meaning or overall proofreading status; meaning-level proofreading is a contextual agent edit logged in `preparationChanges` before layout, not a live checker.

For agent edits use [journal](journal.md) entries with exact before/after text. Keep a single reviewable entry per target so an acceptance or rejection can be applied safely. If a change would cross styled runs or links, edit individual runs in the authored HTML and record it in preparation history. Use `reviewed` only after actually reviewing the declared scope.

## After rendering

```sh
node scripts/check_text_layout.mjs /absolute/new-deck.html
node scripts/check_text_layout.mjs /absolute/new-deck.html --export
```

The first command measures text in normal reading at 1600×900. The second uses Maker's static export state at 1920×1080. Both use the same local Playwright setup as the shell checks. JSON lists editable blocks, actual browser lines and their widths, and candidates for clipping, long prose lines and a short single-word tail. The flags are review candidates. Decorative or transformed text, complex inline typography, and text drawn inside graphics require visual inspection. Read the relevant lines and screenshots, correct the authored HTML/CSS, rebuild to a new file, and recheck the affected slides. Inspect in native PowerPoint when PPTX is requested.

For each actual rendered slide, review these decisions:

- Give each reading group one clear entry point and keep related text together. Check the combined density of title, lead, labels, cards and footnotes, not only whether each box fits. Different content volume needs different composition; do not force everything into equal cards.
- Constrain prose width according to the actual font and content. Avoid page-wide sentences where a narrower paragraph or a paired structure reads better. Conversely, do not make a short paragraph an unnecessarily tall narrow strip.
- Inspect title breaks by meaning, isolated last words and short stranded endings. Adjust the text frame or layout before reducing type. Explicit visual line breaks can preserve wording; retain editable paragraphs and source IDs. Never split every line into a separate editing object.
- Keep short prepositions with their following word where this improves a specific Russian line. Do not run a broad replacement over URLs, identifiers, model names, code or factual numbers. Layout whitespace changes and real editorial changes need different records.
- Browser text-wrap:balance/pretty can assist HTML composition, but are not portable PowerPoint guarantees. Inspect the frozen export state and actual PowerPoint wraps; embedded fonts alone do not make layout engines identical.
- When exact content cannot fit with readable hierarchy, change composition and re-render. Condensing, deleting, splitting/merging slides or adding claims needs the user's request. Do not silently shorten copy or shrink all text.

Use cover, prose, dense table and mixed-graphic slides as representative reviews, then inspect every slide. Record unresolved visible problems and the scope of browser and native export review.

For a concise pre-edit decision, pipe a completed `--actual-fonts --inventory=...` JSON report through `python3 scripts/font_readiness.py report.json --source-id SOURCE_ID --resource-manifest assets/fonts/manifest.json`. Repeat `--source-id` for the affected targets or omit it for all. The summary retains source faces and unresolved inheritance, authored CSS, Chromium's painted font names, and matching local catalog candidates. A catalog candidate or family alias is not proof that a particular file rendered the glyphs. A missing family, mixed fallback, uninspected glyphs or unresolved weight remains a review item; do not assume absent TT Firs Neue has been recovered. The inventory and resource manifest are evidence supplied by the caller, not a universal font discovery engine.

### Explicit private font resources before layout

Before measuring or editing layout, run `preflight.py` and then `font_resources.py --preflight PREFLIGHT.json --font-dir AUTHORIZED_DIR --resource-manifest MANIFEST.json`. A manifest is `{"files":["relative-name.otf"]}`; each named file is read from the paired explicitly supplied directory and is never copied. Without a manifest, explicitly supplying `--font-dir` scans the directory's top-level `.otf` and `.ttf` files. Repeat the paired directory and manifest options to consider more than one resource set. Do not scan or package private fonts without authorization.

An embedded font must first be decoded to a private file using `decode_eot.mjs`, then independently checked: the decoder's `decoded_unverified` status is not identity or license proof. Its manifest entry is `{"path":"decoded.ttf","origin":"embedded","declaredFamily":"Family","declaredFace":"regular"}`; allowed declared faces are `regular`, `bold`, `italic`, `boldItalic`. Actual sfnt `name` and `OS/2` identity and style must match the PPTX declaration. A mismatch is excluded from selection even if its actual font name happens to match another requirement. Keep embedded and local candidates distinct. If multiple exact candidates exist the helper reports ambiguity; use `--prefer-origin local` or `--prefer-origin embedded` only after making an explicit selection. If the preferred origin has no exact candidate, the helper does not silently choose a different origin. Unresolved source style, absent faces and TT Firs without a supplied file remain unresolved.

For an authorized private-only preview, `--private-css NEW.css` generates `@font-face` declarations with unique `gdprivate-*` family aliases and local file URLs for selected exact candidates; each matching resolution records its `cssFamilyAlias`. The stylesheet only declares faces: connect and use the aliases in the local authored preview deliberately before layout, then check actual painted glyphs with `check_text_layout.mjs --actual-fonts`. It does not modify the deck or automatically apply fonts. It is not a portable output. Neither the private stylesheet, path-bearing reports, nor font files should be included in public deliverables without separate rights and privacy review. The sfnt `fsType` field is metadata, not permission to embed or redistribute; local-use authorization alone is not redistribution authorization. Font selection metadata does not prove glyph coverage, shaping, or browser rendering.

To apply a reviewed target-specific mapping in a private preview before layout, run `python3 scripts/font_preview.py INPUT.html MAPPING.json NEW_PRIVATE.html [--private-css PRIVATE.css]`. The mapping has `{"targets":[{"sourceId":"s13-o8","family":"gdprivate-...","weight":300}]}`; use a selected alias and its exact weight for a private face, or an explicitly approved bundled fallback family for a project-specific replacement. Targets must occur exactly once. The preview injects scoped CSS into a new HTML, uses an original-directory base URL for existing media, and copies no fonts. Keep the mapping and preview private, confirm actual target glyph fonts with CDP before measuring, and transfer the reviewed mapping deliberately into the editable project; the preview itself does not modify project JSON. Do not treat it as a self-contained public deliverable.

For a reproducible private rebuild from the editable source project, use `python3 scripts/build_private_fonts.py PROJECT.json NEW_PRIVATE.html --font-map MAPPING.json [--selection SELECTION.json] [--theme THEME.json]`. This calls the ordinary builder and then applies the explicit map, without changing the project; use the same map and selection on every rebuild. For a `gdprivate-*` alias the selection JSON is mandatory and the font file SHA-256 and selected weight/style must still match; a missing target, changed font, wrong mapping or existing output fails without writing a new result. The local file is referenced by URL, not copied or embedded by this step. The ordinary builder may still embed its bundled assets. The output remains private and depends on unchanged local files; do not use this pathway for a public ZIP. The wrapper passes `--typography`, `--external-media`, `--final` and `--composition-plan` to the regular builder. For `--final`, every composition plan `visualReview` must additionally bind `privateFontMapSha256` to the SHA-256 of the reviewed mapping and `privateFontSelectionSha256` to the SHA-256 of the selection (or null when no selection is used); review the candidate with the mapped fonts before recording these values. Standard project and candidate image hash checks still apply. The approved mapping is also recorded as private HTML metadata. The wrapper stages output and media and refuses existing destinations. Full-deck visual QA and public font rights remain separate checks.

For a `gdprivate-*` single-face target, the helper first opens the unmodified build in Chromium and compares computed weight/style of all nonempty text runs. Mixed emphasis, explicit strong/emphasis markup or run-level weight/style, a bold/italic class incompatible with the selected face, generated pseudo-text, or a missing/ambiguous target fails without output: split into independently identifiable runs or review. The bundled-fallback mapping changes the family without overriding per-run weight/style; `allowSyntheticStyle: true` explicitly permits browser-synthesized italic when that face is unavailable. Verify bold and italic in the actual browser, and disclose synthetic styling; do not describe a synthesized face as an exact supplied font. A browser and Playwright are required for the single-face check.

RC14 additionally normalizes individual plain text nodes around strong/em/b/i/span without reconstructing tags. Rules spanning run boundaries and protected links/code remain agent-reviewed. Review those before build and journal exact corrections; do not claim skipped inline text has been proofread.

Short one-letter Russian function words bind to following Cyrillic words with a nonbreaking space in unprotected prose; semantic wording is unchanged.
